digestr

notification batching — a clickable playground

Repo Design API docs

digestr turns N events per recipient into one batch. The first event for a recipient opens a window; later events for that recipient join it. The window flushes exactly once — into a single digest — on whichever trigger fires first: time (the window elapsed) or size (it reached a count ceiling). Under backoff, a lone event is sent straight through and only a repeat is digested. That is the whole job: it groups and windows, and never sends, stores, or templates anything.

Everything below runs in your tab over the pure library compiled to WebAssembly — no backend, no network. digestr owns no timer: the page supplies now to Add and Due, so time only moves when you drag the clock. Instants are shown as seconds from the session start (T+0s). Reload to reset. Built from zkrebbekx/digestr.

How a window flushes

A window flushes exactly once, on whichever trigger comes first. Backoff is a fourth idea — it decides whether an event opens a window at all.

Time — Due(now)

A window opened at T is due at exactly T+Window. Drag the clock past the deadline and it flushes with reason Elapsed. The boundary is inclusive.

Size — MaxSize

Set a count ceiling and the Add that fills a window flushes it at once, reason SizeReached — Knock's batch_size, which bounds latency for a hot key.

Backoff — Lookback

A lone event with no recent send passes straight through, delivered now, opening no window. Only a repeat within the look-back opens a digest. A send starts the horizon.

Add never time-flushes. Adding an event only ever opens a window, joins one, or flushes on size. The time trigger belongs to Due — so a window can sit overdue until you drag the clock or press Flush due now.
